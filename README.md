# BAMP!

[公開サイト](https://bamprogit.github.io/) · [Figma原本](https://www.figma.com/design/1Ht2X1MdhnL3VAjQV2defa/)

Figma「ワイヤーフレーム」の画面、素材、文言、プロトタイプ遷移を静的HTML/CSS/JavaScriptへ実装したサイト。

## ローカル表示

```sh
python3 -m http.server 4173 --bind 127.0.0.1
```

http://127.0.0.1:4173/ をブラウザーで開く。ビルドや依存パッケージのインストールは不要。

## 回答のスプレッドシート保存

FormSubmit の `_webhook` から Google Apps Script の `doPost` に回答を送り、BAMP所有の非公開スプレッドシートへ追記する。Gmail通知とreCAPTCHAは継続する。保存列は受信日時（日本時間）、名前、メールアドレス、現所属、生年月日、電話番号、その他・備考、受付ID。受付IDの重複は追記せず、入力の先頭が数式記号なら文字列として保存する。シートの行数が足りなくなった場合は自動で追加する。

受信側の原本は `entry-webhook.gs`。Apps Script にコピーして `setup` を実行すると回答表を作成し、IDをスクリプトプロパティ `SPREADSHEET_ID` に保持する。既存IDがある場合は再作成しない。所有者として実行するウェブアプリを「全員」からPOSTできる設定でデプロイし、その `/exec` URLを `app.js` の `_webhook` に指定する。回答表の共有は「制限付き」のままにする。コード更新時はウェブアプリのデプロイを新バージョンへ更新する。

受信URLは公開フォームに含まれる。FormSubmitには署名検証の設定がないため、送信元の認証は行わず、必須項目・形式・長さと受付IDを検証する。受付IDは重複防止用で、秘密鍵ではない。ウェブアプリから保存済み回答を返す機能はない。Google側の障害・上限で保存に失敗した場合はApps Scriptの実行ログとGmail通知を照合する。過去のメールの一括取り込みは行わない。

2026-11-10：受信URLへの管理用POST、同一受付IDの重複抑止、回答表のBAMP所有・制限付き共有を確認。公開フォーム経由の確認で受信形式への対応を追加し、17:48 JSTにGmailと回答表へ同じ受付ID・全入力項目が届くことを実画面で確認。JSON内のform_dataがオブジェクト・JSON文字列の両方に対応し、フォーム形式での受信にも対応する。inspectIntegrationは最新の受信形式と保存状態を実行ログへ表示する。

reCAPTCHAが回り続けた際はブラウザのコンソールにreCAPTCHA Timeoutを確認。認証ページの再読み込み後は正常に完了し、続く再送信でも認証と完了画面への遷移を確認した。発生原因の詳細は特定していない。reCAPTCHAやブラウザの保護設定は無効化していない。

2026-11-10本人指定：下層ページ共通フッターを `©2026 BUMP!` に変更。指定された綴りをそのまま使用し、中央配置を維持。

## 画面サイズへの追従（2026-11-10）

入口はPC_top/openingそれぞれの縦横比を保ち、画面の幅と高さの両方に収まる縮尺で中央表示する。背景動画はウィンドウの縦横100%を覆い、余白を作らない。映像の縦横比は維持し、画面比率に応じて端をトリミングする。文字と操作は画面内に収め、ウィンドウサイズ変更・画面回転で即座に再計算する。フォーム・下層は横幅に合わせ、縦方向はスクロールで全内容にアクセスする。PC・スマホの入口とフォームで、PC_topの小さなヘッダーロゴSVGを共用する。ロゴはウィンドウの左上を基準とし、同じウィンドウ寸法で入口とフォームの位置・大きさを揃える。入力欄と重ならない余白を確保し、リサイズ時も入力を保持する。
